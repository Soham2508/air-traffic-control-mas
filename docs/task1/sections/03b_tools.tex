\subsection{Tools and Agent--Tool Matrix}\label{sec:tools}

In keeping with the design principle of Section~\ref{sec:principle} (\emph{tools compute, agents decide}), every safety-relevant computation in ATC-MAS is delegated to a deterministic Python tool exposed to the agents through CrewAI's \texttt{BaseTool} interface~\cite{crewai} with typed Pydantic schemas. Agents never perform mental arithmetic, estimate separations, or certify plans from language-model reasoning alone; instead, they invoke the assigned tools, interpret the structured outputs, and record justified decisions.

\textbf{Custom Tools (\texttt{T4} and \texttt{T5}).} The two core tools encapsulate all geometric separation checks and manoeuvre searches:
\begin{itemize}[leftmargin=*]
    \item \textbf{\texttt{T4 -- ConflictDetectionTool} (Agents~4 and~7):} Enables deterministic pairwise trajectory comparison. For every pair of time-overlapping flight segments, it computes the closest point of approach (CPA) and flags a conflict whenever horizontal distance is at most $5\,\text{NM}$ \emph{and} vertical distance is at most $1{,}000\,\text{ft}$ at the same time~\cite{icao4444}. Beyond the baseline CPA coordinates and distances, \texttt{T4} outputs the loss-of-separation entry and exit timestamps ($t_{\text{LoS}}$ and duration), track-angle difference and encounter geometry (same track, head-on, or crossing), severity metric $m$, and a deterministic priority ordering saved to \texttt{conflicts.json} (Section~\ref{sec:resolution}). \texttt{T4} is shared by Agent~4 for initial detection and by Agent~7 for independent full-traffic re-checking.
    \item \textbf{\texttt{T5 -- ManeuverCalculationTool} (Agent~5):} Serves as the deterministic tactical planning engine in two modes. In \emph{generate} mode, given a ranked conflict and all active flight plans, it enumerates the discrete manoeuvre catalogue (flight-level changes of $\pm 1{,}000$ or $\pm 2{,}000\,\text{ft}$, speed adjustments of $\pm 10$ or $\pm 20\,\text{kt}$, and departure delays of $+60$, $+120$, or $+300\,\text{s}$) for both conflicting aircraft, applies each candidate to a copy of the scenario, and evaluates it against aircraft limits and full-traffic separation using \texttt{T4}'s detection logic. Any candidate that fails to resolve the conflict, introduces a secondary conflict, or exceeds performance bounds is discarded; surviving candidates are ranked deterministically by preference order and tie-breaking rules (Section~\ref{sec:resolution}). In \emph{evaluate} mode, \texttt{T5} applies the exact same separation and limit checks to alternative waypoint routes proposed by Agent~6 (\texttt{T6}) before writing \texttt{resolutions.json}.
\end{itemize}

\textbf{Supporting Deterministic Tools (\texttt{T1}--\texttt{T3}, \texttt{T6}--\texttt{T8}).} The remaining six tools handle input preparation, trajectory projection, graph rerouting, independent constraint auditing, and final reporting:
\begin{itemize}[leftmargin=*]
    \item \textbf{\texttt{T1 -- AirspaceGraphLoaderTool} (Agent~1):} Parses the GraphML airspace file into a directed graph, verifies that every node carries finite \texttt{latitude} and \texttt{longitude} attributes and every directed edge carries a positive \texttt{distance\_nm}, and emits structured validation issues if the graph is malformed.
    \item \textbf{\texttt{T2 -- FlightDataNormalizerTool} (Agent~2):} Parses the aircraft and flight-plan JSON files into strict Pydantic \texttt{FlightPlanModel} records, enforces uniform units (\texttt{NM}, \texttt{ft}, \texttt{kt}, \texttt{s}) and non-negative timestamp ordering, and runs cross-file referential checks (unique aircraft identifiers, valid aircraft references, minimum route length, and valid directed edges in the GraphML network). It writes \texttt{normalized\_scenario.json} or emits \texttt{INVALID\_INPUT} diagnostics so Router~A can bypass downstream crews.
    \item \textbf{\texttt{T3 -- TrajectoryExtrapolatorTool} (Agent~3):} Projects waypoint coordinates onto a local equirectangular plane centred on the mean latitude and longitude of the airspace nodes and computes piecewise-linear 4D trajectories $(x(t), y(t), z(t))$ assuming constant cruise speed and altitude per leg.
    \item \textbf{\texttt{T6 -- AirspaceGraphRoutingTool} (Agent~6):} Searches the directed GraphML network for alternative origin-to-destination waypoint paths avoiding the conflicting airway segment whenever \texttt{T5} finds no feasible altitude, speed, or delay manoeuvre. Candidate routes are passed back through \texttt{T5} (\emph{evaluate} mode) before selection.
    \item \textbf{\texttt{T7 -- ConstraintCheckerTool} (Agent~7):} Independently verifies every amended flight plan against aircraft performance limits (speed bounds and service ceiling) and, when provided, active airspace or weather restrictions. Combined with \texttt{T4}'s full-traffic re-check, \texttt{T7} produces \texttt{VALIDATED} or \texttt{REJECTED} verdicts in \texttt{validation.json} using explicit reason codes (\texttt{SECONDARY\_CONFLICT}, \texttt{TARGET\_NOT\_RESOLVED}, \texttt{LIMIT\_VIOLATION}, or \texttt{RESTRICTION\_VIOLATION}).
    \item \textbf{\texttt{T8 -- MarkdownReportRendererTool} (Agent~8):} Reads the validated intermediate JSON artefacts (Table~\ref{tab:crews}) and renders the deterministic Markdown report \texttt{atc\_report.md}. Agent~8 assigns the flight clearance statuses (\texttt{CLEARED}, \texttt{CLEARED WITH AMENDMENT}, or \texttt{NOT CLEARED}) using \texttt{T8}, which applies the rules of Table~\ref{tab:clearance} deterministically. Agent~8 may add explanatory narrative, but \texttt{T8} prevents any LLM modification of computed numbers or statuses.
\end{itemize}

\subsubsection{Extended Input Schemas}\label{sec:input-schemas}

As introduced in Section~\ref{sec:inputs}, the baseline dataset specifies only \texttt{id} and \texttt{speed\_kt} for each aircraft, which is insufficient to check whether a candidate speed or flight-level manoeuvre is physically achievable. We therefore extend the aircraft JSON schema with four performance fields (Table~\ref{tab:aircraft-schema}) and define an optional \texttt{restrictions.json} schema (Table~\ref{tab:restrictions-schema}) for weather cells and closed airspace elements.
